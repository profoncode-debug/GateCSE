Compiler Design

In the von Neumann stored-program model, instructions and data share memory; the CPU contains registers, an ALU for arithmetic and logical operations, and a control unit that decodes instructions and coordinates execution. Instructions follow the cycle fetch → decode → fetch operands → execute → write back. A CPU's instruction set defines the operations it supports; unsupported operations must be implemented using supported instructions. Machine language consists of binary instructions directly understood and executed by the processor, whereas assembly language uses mnemonics translated into machine code by an assembler, usually with a one-to-one instruction mapping (except macros and pseudo-instructions). Both machine and assembly languages are processor-dependent; high-level source code is generally portable but requires translation for the target platform. Machine code needs no prior translation, but translation time differs from execution time: programs producing the same machine instructions execute equally fast under the same conditions, regardless of their source language.

1. Front-end and back-end independence: The front end is designed to be independent of the target machine, while the back end is designed to be independent of the source language. A common intermediate representation (IR) connects them.

2. Intermediate code optimization: Code optimization phases are optional; a compiler can generate correct target code without them. Optimization adds implementation complexity and can increase compilation time, so it may be disabled. In a two-phase view, IR optimization may be grouped with the back end; in a three-phase view, it belongs to the middle end. We will follow the three-phase view for IR optimization.

GATE CSE 2023: Front End and Back End

Consider the following statements regarding the front-end and back-end of a compiler.

  • S1: The front-end includes phases that are independent of the target hardware.
  • S2: The back-end includes phases that are specific to the target hardware.
  • S3: The back-end includes phases that are specific to the programming language used in the source code.

Identify the CORRECT option.

  1. Only S1 is TRUE.
  2. Only S1 and S2 are TRUE.
  3. S1, S2, and S3 are all TRUE.
  4. Only S1 and S3 are TRUE.
Answer: B — Only S1 and S2 are TRUE. The front end handles source-language analysis independently of the target hardware. The back end generates code for the target hardware from IR, independently of the original source language; hence S3 is false.

M*N vs M+N

Why use intermediate code? Generating target code directly from source code is possible without IR. A common IR makes compiler components reusable across source languages and target machines.

Let M = number of source languages and N = number of target machines.

  • Without a common IR: M*N. A separate direct compiler is needed for each language-machine pair. For 5 languages and 4 machines: 5*4 = 20 compilers.
  • With a common IR: M+N. Build M language-specific front ends and N machine-specific back ends. For the same example: 5+4 = 9 components, which can be combined to support all 20 pairs.
  • Shared optimization: one optional IR optimizer can serve these combinations. It is counted separately from the M+N front ends and back ends.
Adding support: A new source language needs one new front end; a new target machine needs one new back end, provided they use the common IR.

Lexical Analyzer

Lexical analysis / scanning / tokenization is the first phase of a compiler. It reads source characters from left to right and groups them into tokens for the syntax analyzer.

Character stream → Lexical Analyzer → Token stream
  • Lexeme: the actual sequence of source characters matched to a token, e.g. sum.
  • Token: represented as <token-name, attribute>. The token name identifies the category; the optional attribute provides a value or a reference to a table entry.
  • Symbol table: the lexer records identifiers or looks up existing entries; an identifier token can carry a pointer to its entry. Later phases add information such as types.
  • Whitespace and newlines: normally skipped in C-like languages; they separate lexemes but do not produce tokens in this example.

Example: int sum = 9;

LexemeToken (illustrative)
int<INT, —>
sum<ID, pointer to sum's symbol-table entry>
=<ASSIGN, —>
9<NUMBER, 9>
;<SEMICOLON, —>

Total: 5 tokens. Spaces generate no tokens. — indicates no attribute is needed; a number token may alternatively refer to a constant-table entry.

Lexical Analyzer: Questions

Q1. Token Count: Declaration and Assignment

How many tokens are generated for the following C code?

int a;
a = a + 2;

Tokens: int · a · ; · a · = · a · + · 2 · ;

Answer: 9 tokens. Every occurrence of an identifier counts as a separate token.

Q2. Token Count: while and Increment

How many tokens are generated for the following C code?

while (ip < z)
    ++ip;

Tokens: while · ( · ip · < · z · ) · ++ · ip · ;

Answer: 9 tokens. ++ is one token; + +, separated by whitespace, is two tokens.

Q3. Token Count: printf and String Literal

How many tokens are present in this C statement?

printf("Total = %d\n", score);

Tokens: printf · ( · "Total = %d\n" · , · score · ) · ;

Answer: 7 tokens. The entire string literal is one token, including its spaces, format specifier, and escape sequence.

Q4. Token Count: printf and Address Operator

How many tokens are present in this C statement?

printf("i=%d, &i=%x", i, &i);

Tokens: printf · ( · "i=%d, &i=%x" · , · i · , · & · i · ) · ;

Answer: 10 tokens. Outside the string, & and i are separate tokens; everything inside the quotes belongs to one string-literal token.

Q10. Maximal Munch: Scanner Output

What output does this scanner produce for (i) aaabccabbb, (ii) cbbbbac, and (iii) cbabc?

a*b       printf("1");
(a|b)*b   printf("2");
c*        printf("3");
(i) aaab | cc | abbb → 132. For aaab, rules 1 and 2 tie, so rule 1 wins.
(ii) c | bbbb | a... → 32, then lexical error at a under the error convention below.
(iii) c | bab | c → 323.

Choose the longest nonempty prefix; break equal-length ties using the earlier rule. An empty match of c* does not consume an unmatched a.

Q13. Scanner Time Complexity: Quadratic Rescanning

For a conventional maximal-munch scanner that rescans after backing up, which input takes Θ(n2) time? Here an denotes n copies of a.

a*b   { return 1; }
a     { return 2; }
  1. an
  2. anb
  3. an2
  4. bn
Answer: A — an. Each attempt searches for a final b, reaches the end, then backs up to accept one a. Work is n + (n-1) + ... + 1 = n(n+1)/2, hence Θ(n2). For anb the first rule matches in one pass; an2 takes Θ(n4) under the same model.

Lex as DFA

Lex scans the input to find the longest matching token, then restarts the DFA from its start state at the first character after that token. It remembers the last accepting state; if a later transition fails, it backs up to that token boundary.

Lexical Errors

Errors detected by the lexical analyzer during scanning (tokenization).

  1. Invalid token formation: a character sequence cannot form a valid token under the language's lexical rules; tokenization fails. This differs from a grammatically invalid sequence of valid tokens, which is a syntax error.
  2. Invalid or unknown characters: characters not allowed in the current context, e.g. @ or $ outside strings and comments in standard C.
  3. Unterminated string literal: a string is missing its closing quotation mark, e.g. "Hello world.
  4. Unclosed comment: a multiline comment starts with /* but has no closing */, e.g. /* Hello world....

Q15. Lexical Analysis: True Statements

Which of the following statements is/are true?

  1. Lexical analysis is recursive in order to handle nested parentheses.
  2. Scanners don't know anything about the grammar of a language.
  3. A regular expression is a type of pattern used to classify lexemes.
  4. You can change state in a DFA without reading any input character.
Answer: B and C.
  • A — False: nesting is checked by the parser; the lexer recognizes individual parenthesis tokens.
  • B — True in the intended sense: a scanner uses lexical rules, rather than the syntax grammar that determines how tokens form statements.
  • C — True: regular expressions specify token patterns that match lexemes.
  • D — False: every DFA transition consumes an input symbol; DFAs have no epsilon transitions.

Q16. Ada Identifier: Minimum DFA States

In Ada, an identifier must begin with a letter and can be followed by zero or more letters, digits, or underscore symbols. However, two underscores may not appear in a row, and the last character may not be an underscore. What is the minimum number of states required for a DFA to accept all valid identifiers?

Answer: 4 states, including the dead state. Track whether no character has been read, the current prefix ends in a letter/digit, it ends in an underscore, or it is already invalid.

q0: Startq1DeadDead
q1: Letter/digit ending (accepting)q1q1q2

Why minimal? q1 is the only accepting state; a digit distinguishes q0 from q2, and a letter distinguishes either from Dead. Thus all four states are necessary. A diagram omitting the dead state shows only 3 states, but represents a partial DFA.

6. Left factoring

  • Non-left-factored grammar: two or more alternatives of the same nonterminal have a common nonempty prefix.
  • Left-factored grammar (LFG): no two alternatives of any nonterminal share a nonempty prefix.
  • Left factoring: a grammar transformation that extracts shared prefixes while preserving the generated language. It postpones the parser's choice until after the common prefix.

Transformation Rule

The common prefix α ≠ ε can be a sequence of terminals, nonterminals, or both. Introduce a new nonterminal A′:

Before:
A → αβ1 | αβ2 | ... | αβn | γ

After:
A → αA′ | γ
A′ → β1 | β2 | ... | βn

Here γ represents alternatives that do not start with α. If an alternative is exactly α, its remaining suffix is ε. Repeat until no shared prefixes remain.

Example: Common Prefix with Nonterminals

S → iEtS | iEtSeS | a
E → b

The common prefix is α = iEtS. Factoring gives:

S → iEtSS′ | a
S′ → eS | ε
E → b

Nullable-Prefix Note

For S → Xa | Xb, X → ε, substituting X gives S → a | b, which is left factored. As written, the original alternatives still share the grammar-symbol prefix X under the standard syntactic definition, even though X generates only the empty string.

Remember: left factoring alone does not guarantee an LL(1) grammar or remove left recursion. Left-factoring reference.

7. Left recursion

A grammar is left recursive if some nonterminal A can derive a sentential form beginning with itself: A ⇒+ Aα, in one or more derivation steps.

  • Immediate (direct) left recursion: a production directly starts with its own left-hand nonterminal, e.g. A → Aα | β.
  • Indirect left recursion: the recursion passes through other nonterminals. For S → Aa | b and A → Ac | Sd | ε, S ⇒ Aa ⇒ Sda. This grammar also has immediate left recursion in A → Ac.

Eliminating Immediate Left Recursion

For A → Aα | β, repeated recursive steps followed by β produce β, βα, βαα, and so on: the pattern βα*.

A → βA′
A′ → αA′ | ε

A′ is a new nonterminal, α is nonempty, and β does not begin with A. The transformation preserves the language.

Generalized Rule

Before:
A → Aα1 | Aα2 | ... | Aαm | β1 | β2 | ... | βn

A → β1A′ | β2A′ | ... | βnA′
A′ → α1A′ | α2A′ | ... | αmA′ | ε

Separate recursive alternatives from nonrecursive ones, attach A′ to each β, and move each recursive suffix α into A′. This rule removes immediate recursion; indirect recursion may require substitution first.

8. Removing indirect left recursion

Given: S → Aa | b, A → Ac | Sd | ε.

  1. Fix an order: S, A.
  2. Process in order: S has no earlier nonterminal to substitute and no immediate left recursion, so it stays unchanged.
  3. Find the earlier leading nonterminal: in A's production A → Sd, S comes before A.
  4. Substitute: replace S using S → Aa | b, giving A → Ac | Aad | bd | ε.
  5. Remove immediate left recursion: recursive suffixes are c and ad; nonrecursive alternatives are bd and ε. Apply the standard rule with a new A′.
Final grammar:
S → Aa | b
A → bdA′ | A′
A′ → cA′ | adA′ | ε

Key idea: substitution exposes indirect recursion as direct recursion, which is then eliminated. Here εA′ = A′.
